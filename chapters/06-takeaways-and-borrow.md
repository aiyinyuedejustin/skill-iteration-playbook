# 6. 要点，以及可以从别处借什么

## 这件事的意义

skill 迭代本质上是把软件工程的老办法搬到自然语言上：先写测试，小步修改，看日志找原因，重构去冗余，发版前跑回归。不同之处在于：被测对象会随机波动，判分本身可能出错，而且 agent 可能找到评测的漏洞。

研究趋势也指向同一方向：从 APE、OPRO 靠大量搜索，到 GEPA、BudgetAPO、EvoSkill 靠读轨迹反思并在 skill 层进化，再到 ACE、Voyager 把经验积累成条目——方法越来越像一个认真的工程师在做的事。自动化在提高，但评测集、判官和「这条规则是不是通用」的判断，现在仍然主要靠人。

## 十条要点

1. 先有评测，再改 skill。哪怕只有 3 道题。
2. 分开测触发和正文。
3. 永远同时跑带 skill 和不带 skill，看差值。
4. 优先判结果和环境状态。
5. 断言要有区分度：错误输出也能通过的断言比没有更糟。
6. 模型判官用二元判断加理由，并用人工标注持续校准。
7. 改之前读轨迹，记第一个错误，归类计数，先改最常见的。
8. 规则写做法，不写答案。
9. 每隔几轮只删不加；删的标准是留出集分数不掉。
10. 跑一次很贵时：分层跑、存轨迹、断点续跑；限流交给脚本。

## 最短上手路径

1. 拿 3 到 6 道你知道答案的题，不带 skill 跑一遍，记下失败。
2. 带 v1 跑一遍，存下全部轨迹。
3. 读轨迹，归类，挑最常见的一类，写成一条通用做法。
4. 在没用来改的题上再跑一遍，没变差就提交成 v2。
5. 重复，每两三轮剪一次。

## 可借用的思路（间接来源）

下面这些材料不是为「迭代 Agent Skill」写的。能借的是心态和结构，不是名词和流程的硬套。带「推测」的句子是引申，不是原文结论。

### 测试驱动开发 → 先场景后 skill

superpowers 的 writing-skills 已经把 TDD 映射成：先写压力场景，看着无 skill 时失败（RED），写下 agent 给自己找的理由，再写最小 skill（GREEN），再堵漏洞（REFACTOR）。

**可抽取的心态**：没失败证据就不要加指令。

**改写成 skill 迭代**：每一条新规则必须对应至少一道会因缺少它而失败的题；规则进正文之前，先跑出那道题的失败轨迹。

### 代码坏味道 → skill smells

Martin Fowler 意义上的 smell 是「值得停下来闻一闻的信号」，不是自动判死刑。skill smells 论文把 26 条编写建议反转成 26 种可检测坏味道，并发现真实仓库里几乎无处不在、且很少被后续提交清掉。

**可抽取的心态**：质量问题要可命名、可检测，否则迭代只会越堆越长。

**改写成 skill 迭代**：发版检查单里加一项「扫 smells」；剪枝时优先处理 Undelegated Details、过长正文、过短描述这类高频项。**推测**：把 smell 检测接到 CI，比只写在指南里更可能真的减少坏味道——论文本身也呼吁自动化修复，但尚未证明某种修复策略一定有效。

### A/B 实验与配置 bundle → 发版纪律

在线实验的纪律是：先定主指标和护栏指标，样本量够了再下结论，能回滚。AgentCore 把系统提示词和工具描述打成不可变 bundle，再用网关做流量分叉。

**可抽取的心态**：行为变更与代码发布解耦；对比要有统计意识。

**改写成 skill 迭代**：每个 skill 版本对应一份冻结的评测报告；主指标用留出集通过率，护栏用回归集和成本（耗时/token）；达不到就回退 git 标签。题极少时谈不上显著性——老老实实标「待确认」。

### 精益 / 改善 → 小步、看现场

改善（Kaizen）强调到现场看、小步改、标准化再下一步。

**可抽取的心态**：改进来自对真实失败的观察，不来自会议室里的想象。

**改写成 skill 迭代**：Hamel 说的「先看数据 / 读轨迹」就是现场；一轮只改一两类失败就是小步；把稳定通过的题移入回归集就是标准化。**推测**：把「错误分析会议」固定成每周一次读 20 条轨迹，可能比上新优化器更能提升 v2 质量——这与 Hamel「60%–80% 时间花在错误分析」的经验一致，但是否适合你的团队要自己试。

### 数据科学里的「先假设再度量」

《The Revenge of the Data Scientist》提醒：不要拿现成的通用指标（「有帮助」「连贯」）顶替对你产品真实失败的度量。

**可抽取的心态**：指标是假设的结果，不是起点。

**改写成 skill 迭代**：先错误分析，再决定写哪条断言；eval-audit 里「缺少错误分析就去造判官」被标成高优先级问题，原因就在这里。

## 仍薄的地方

- 推特/X 上的碎片经验没有系统收录，只吸收了已写成文章或仓库的部分。
- Google/DeepMind、Meta 几乎没有专门讲 skill 迭代的一手材料。
- 长任务降本的若干新论文未纳入（未充分核对）。
- 间接来源的「改写」是工作建议，不是受控实验结论。
