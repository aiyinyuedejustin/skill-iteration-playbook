# 10. 回归检查和发版

改出 v2 之后，最怕的是新问题修好了，旧的又坏了。

## 两类评测分开维护

Anthropic 的评测文章把评测分成两类：

- **能力评测**：测 skill 还做不好的事，分数应该随迭代上升。
- **回归评测**：测已经做好的事，分数应该一直接近满分。一旦掉了，就是改坏了。

一道能力评测题稳定通过以后，把它移进回归集。每次发版前回归集必须全部跑一遍。

## 版本管理

把 skill 当代码管：

- 每个版本都提交到 git，改动说明写清楚这一版针对哪类失败。
- 每个版本的评测结果和版本号一起存，方便以后比较。skill-creator 把每一轮的结果放在单独的迭代目录里。
- 留着上一版，新版有问题时能直接退回。OpenAI 的自我进化 agent 示例也包含版本记录和回退。

## 模型升级以后

skill 是写给某个模型的，模型换了，原来的一些说明可能变得多余，也可能变得不够。skill-creator 的博客专门提到 benchmark 模式适合在模型更新后跑。做法：

1. 新模型上把回归集和带不带 skill 的对比都跑一遍。
2. 如果不带 skill 的分数已经追上带 skill 的，说明 skill 里有一部分内容新模型已经会了，可以考虑删减。
3. 如果有题从通过变成失败，按第 6 章读轨迹，不要直接加规则。

## 发版检查单

- 留出集分数不低于上一版。
- 回归集全部通过，或者每一个失败都有解释。
- 带 skill 和不带 skill 的差值仍然为正。
- 正文没有比上一版明显变长；如果变长了，能说出新增的每一段对应哪类失败。
- 检查一遍新增的规则，确认没有一条写的是具体题目的答案。

## 小结

能力评测和回归评测分开维护，skill 按代码的方式做版本管理，模型升级后重跑并考虑删减。
