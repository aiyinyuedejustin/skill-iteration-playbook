# 3. 迭代到底在优化什么

改 skill 之前，先回答一个问题：v2 比 v1 好，好在哪？说不清这一点，后面所有的改动都只是凭感觉。

## 要决定的第一件事：一个 skill 有两种失败

Anthropic 的 skill-creator 把 skill 的问题分成两类，分开测、分开改：

- **该用的时候没被用上，或者不该用的时候被用上了**。这取决于 skill 开头的 `name` 和 `description`。按 Agent Skills 的设计，agent 启动时只读到每个 skill 的名字和描述，觉得相关才去读正文，正文里引用的文件再按需打开（官方叫渐进式披露）。所以描述写得太宽会误触发，太窄就永远不触发。
- **用上了，但做得不对**。这才是正文的问题。

这两类问题的测法完全不同。触发问题可以用几十条短查询快速测，skill-creator 的做法是准备大约 20 条「应该触发」和「不应该触发」的查询，按六四分成训练集和留出集，每条跑 3 次算触发率，最多改 5 轮，最后按留出集的分数挑最好的描述。正文的问题则要跑完整任务才看得出来。

**怎么选**：如果你的 skill 是用户明确点名调用的（比如「请使用这个 skill」），触发问题基本不存在，精力全放在正文上。如果是让 agent 自己挑，先把触发测一遍，因为正文写得再好，不触发也是零分。

## 要决定的第二件事：「变好」用什么衡量

可以选的指标大致有这几类：

| 指标 | 适合 | 代价 |
| --- | --- | --- |
| 结果对不对（测试通过、分数对上、状态正确） | 有明确正确答案的任务 | 要先有可靠的判法 |
| 过程是否合规（按要求的步骤做、没做禁止的事） | 流程类 skill | 要读轨迹，往往得靠模型判或人判 |
| 成本（时间、token、工具调用次数） | 所有 skill | 容易测，但不能单独当目标 |
| 稳定性（跑多次都成功的比例） | 要上生产的 agent | 每题要跑多次，贵 |

Anthropic 的《Demystifying evals for AI agents》建议尽量判结果和环境状态，而不是判 agent 最后说了什么，因为 agent 会声称自己做完了而实际没做完。skill-creator 的 benchmark 模式同时记通过率、耗时和 token，并且总是同时跑「带 skill」和「不带 skill」两组，看差值。这一点很重要：**skill 的价值是它带来的差值，不是带 skill 时的绝对分数**。如果不带 skill 也能做对，这道题就测不出 skill 的作用。

稳定性有两种算法。pass@k 是跑 k 次至少成功一次的比例，适合「能找到一次成功就行」的场景；pass^k 是 k 次全成功的比例，适合「每次都得成功」的场景。给 agent 用的 skill 大多属于后者。

## 要决定的第三件事：哪些问题归 skill，哪些归 harness

agent 跑起来是「模型 + harness + 工具 + 环境 + skill」一起在工作。失败了不一定是 skill 的错：可能是 harness 没做重试、工具返回的报错不清楚、容器里缺依赖，或者模型本身做不到。

一个实用的划分：

- **该由 harness 或工具解决的**：重试和退避、超时、限流、日志、环境准备。写进 skill 里让模型每次自己处理，既不可靠又费 token。Anthropic 的《Writing effective tools for agents》也是这个思路：工具的报错信息写清楚，比在提示词里教模型怎么猜要可靠。
- **该由 skill 解决的**：判断和做法。哪些地方容易做错、按什么顺序查、做完怎么自己检查、遇到某类情况怎么处理。
- **两边都不该管的**：模型能力本身达不到的。这种情况换模型，或者把任务拆小。

分清这一点，可以省掉大量无效的 skill 改动。第 6 章讲错误分析时，归类的第一步就是先判断这个失败属于哪一边。

## 要决定的第四件事：skill 写给谁看

skill 的读者是模型，不是人。Anthropic 的《Skill authoring best practices》有几条值得记住的原则：

- 默认模型已经很聪明，只写它不知道的东西。每一段都问一句：模型真的需要这句吗？
- 自由度要跟任务的脆弱程度匹配。容易出错、顺序很关键的操作写死成步骤或脚本；有多种合理做法的地方只给原则。
- 正文控制在 500 行以内，细节拆到单独的参考文件，引用只保留一层深。
- 用你打算实际使用的几个模型都测一遍，因为对大模型够用的说明，小模型可能看不懂，反过来对小模型必要的细节，大模型可能嫌啰嗦。

这些原则决定了迭代的方向：大多数时候 v2 不应该比 v1 长很多。如果每一轮都只往里加东西，第 8 章会讲怎么删。

## 小结

先分清触发问题和正文问题，定下用什么指标衡量「变好」，并把限流、重试这类确定性的事交给 harness。skill 的价值是带它和不带它的差值。
